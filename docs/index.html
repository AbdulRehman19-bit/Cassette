ChangelogCat

Push a tag. Get user-facing release notes in your GitHub Release, written from the PRs that shipped in it.

It is a small GitHub Action built to be tested: it is the live test subject of Cassette, a record-and-replay testing tool for agents.

Add it in two minutes

  1. Get a free API key at console.groq.com/keys and save it in your repository as a secret named GROQ_API_KEY (Settings, Secrets and variables, Actions).
  2. Add this file as .github/workflows/release-notes.yml:
name: release notes
on:
  push:
    tags: ["v*"]

jobs:
  notes:
    runs-on: ubuntu-latest
    permissions:
      contents: read          # the agent can only read
    steps:
      - uses: AbdulRehman19-bit/Cassette/examples/changelogcat@main
        with:
          api-key: ${{ secrets.GROQ_API_KEY }}

  publish:
    needs: notes
    runs-on: ubuntu-latest
    permissions:
      contents: write         # only this job can write
    steps:
      - uses: AbdulRehman19-bit/Cassette/examples/changelogcat/publish@main
  1. Push a tag like v1.2.0. The notes appear in the Release body, compared against your previous version tag.

Why it is safe to run on your repo

ChangelogCat reads text written by strangers (PR titles and bodies) and publishes AI output, so a hostile PR could try to steer it. It is built in layers, so no single failure is enough:

  • It cannot write. The agent runs in a job with contents: read, talks to GitHub through a server that only makes GET requests, and exposes just four read tools.
  • Publishing is separate. A second job, with no agent code and no model key, is the only thing that edits the Release.
  • Links are filtered. Anything the model writes that does not point into your repository is removed before publishing.
  • It is tested. Cassette replays recorded runs in CI and fails a change that adds a forbidden tool call or leaks a planted secret.

Early software. It uses a free-tier model by default, so quality and rate limits vary; for large releases choose a stronger model with the provider and model inputs. Always skim the notes before announcing a release.
